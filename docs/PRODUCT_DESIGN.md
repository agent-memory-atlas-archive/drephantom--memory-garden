# Memory Garden：让回看由用户掌握节奏

更新：2026-09-07。本文区分已实现的行为与下一步需要验证的假设。

## 从用途出发

用户已经有地方写笔记，也有通用聊天工具。这里需要解决的，是过了一段时间之后，怎样找回当时的原话，
看见尚未主动提出的问题，并保留对自己经历的解释权。

认知回溯首先是一段可以连续交流的对话。模型要理解用户是在查过去、补充现在，还是讨论一个一般问题。
“没有足够私人记录”只限制私人事实结论，不应该阻止一般交流，也不应该变成每轮索要材料的模板。

一次回看应尽量只要求用户做一个小决定：是否想继续看这条线索。证据放在身边，
展开时能找到；不强迫用户阅读流程、理解检索参数、填写判定表，或每天回来打卡。

长期的“记忆花园”愿景包含记忆的持续积累与主动授权的交流。当前版本先把单人的来源、修订和反馈做好，
没有实现跨用户 Agent 交流，也没有把私人记录共享到外部。

## 已落地的交互

- 首页支持“找一条回看线索”，手动触发少量候选；并排呈现两端原话与日期。
- 对话保留行内来源按钮，打开回答时保存的片段、记录/事件时间和文件位置。列表只包含正文实际引用的条目。
- 反馈入口为“这贴近我的想法”“补充或修正”“暂时放着”。用户可以写出更准确的说法，刷新后保留已反馈状态。
- 对发现线索选择“暂时不看”会暂缓同一对原子七天；它不写入观点判定，不等于“我不同意”。
- 新的回看总是从空会话开始；只有打开明确的历史链接才恢复旧对话。
- 首页显示合成演示、本地回看或云端连接状态；高级检索参数放在设置的折叠区域。
- 等候不显示不断增长的秒数；请求失败显示真实类别并提供恢复原问题的操作。
- 多轮回答保留话题、等待中的追问和本次对话里的补充；接到补充后不再重复索要当前看法。
- 明确暂停、暂时说不清、换话题、继续查旧记录分别处理。聊天补充保留为本段对话内容，不自动写为长期观点判定。
- 连接模型后，由模型结合历史决定交流、查原话、认知回溯或发现线索。一般交流可直接回应；涉及私人事实才进入工具循环。
- 工具循环通过独立的最终回应字段交付正文，过程文字不作为聊天消息显示。模型失败明确告知，不悄悄换成模板。
- “Agent 演示”使用已配置生成模型、合成 Vault 和独立对话库；“离线演示”明确标为模板对照。
- 窄屏使用单列、可伸缩输入框和紧凑导航；中文输入法确认候选时不误发消息，支持键盘焦点和减少动画偏好。

## 对可信度有实际影响的修复

- 已被发现候选引用的片段不再在同步时删除，避免外键失败和历史来源丢失。旧片段退出当前检索。
- schema v4 升级前创建 SQLite 备份。当前原子带版本标记，长章节不再静默截掉 4000 字以后的内容。
- 行号计入 frontmatter；原始笔记保持只读。解析版本变化会在下次同步时重建当前索引，历史片段保留。
- 数据库绑定笔记库根目录，拒绝静默切换；不存在的路径不能被误当成“全库删除”。
- 离线模式不会因为曾保存生成模型 Key 而启用发现分类或快照抽取的云端连接。
- 工具调用预算逐个检查；工具和网络重试共享剩余时间。时间预算为协作式约束，不能强行中断任意阻塞的第三方函数。
- 模型读取来源后，不能通过删除全部引用绕过引用守卫。守卫仍不等于每个自然语言主张都已被语义验证。
- 本机 Web 校验 Host、Origin 与跨站请求；设置保存先校验组合，错误不会再显示成成功。
- 向量查询批量读取缓存，去掉每条候选单独查询 SQLite 的循环。仍然是线性余弦扫描，没有声称适用于任意规模。

## 两分钟演示

1. 配好生成连接并启动 `start-agent-demo.bat`，首页确认“Agent 演示 · 模型名 · 合成记录”。
2. 选择“自主判断”，核对引用的原话与时间。
3. 追问“为什么人的想法会变化”，检查回应是否承接上下文，而不是重复索要当前看法。
4. 再问“2019 年的原话是什么”，应重新查来源；随后说“今天先到这里”，应尊重暂停。
5. 在历史里回到原对话；这些合成场景只验证交互链路，不代表真实用户收益。

## 接下来优先验证什么

| 问题 | 需要的证据 | 优先级 |
|---|---|---|
| 线索是否有意义，而非只共享关键词 | 所有者独立标注候选的相关性、真假变化、是否值得回看 | 高 |
| 引用是否真的支持相邻的主张 | 按主张检查 faithfulness；不只检查引用编号是否存在 | 高 |
| 主题拆分与合并是否合理 | 同义词、含糊主题、相似主题的专门评测集 | 高 |
| 更长的真实记录是否仍然快速 | 固定设备下不同原子数量的延迟、内存与索引耗时 | 中 |
| 用户是否容易表达不同意 | 合成任务可用性测试：找到来源、修正误解、放下线索、返回历史 | 中 |

避免把停留时长、连续签到或消息数当成主要成功指标。更值得观察的是：用户能否找到原话、
能否轻松修正错误，以及回看之后是否愿意确认“这条有意义”。这些仍是待验证的产品假设。
